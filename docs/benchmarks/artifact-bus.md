# Artifact bus — hop benchmarks

Generated by `scripts/bench_pipeline_hops.py`. `stub` rows measure the
serialization work with representative payloads; `engine` rows are real
requests against real weights (HuggingFace cache, CPU).

## Method

- **Stub mode** (`--mode stub`, no weights): reproduces exactly the pre-Phase-2
  intermediate representation for the two worst hops and times it against the
  artifact pass-through:
  - `voicefixer_mel_hop` — `base64(JSON(list[float]))` of a `[1, 100, 128]`
    VoiceFixer mel (~1 s at hop 441) encode + decode, versus handing the
    `MelArtifact` reference to the next step.
  - `synth_to_tone_converter` — PCM-16 WAV encode + base64 + base64 decode +
    WAV decode of a 1 s waveform, versus handing the `AudioArtifact`.
- **Engine mode** (`--mode engine`): boots `AsyncHarmonySpeech` for a family and
  runs full requests. Executor entry points are instrumented for per-step wall
  time; `tracemalloc` records the first-run host allocation peak; codec calls
  are counted (`decode_calls` should be one per request at admission,
  `encode_calls` zero inside the engine).
- `--determinism` runs the same request twice and compares the final waveform
  bytes (SHA-256), duration and RMS.

The VoiceFixer mel hop was the dominant internal cost: **~25.4 ms and ~0.98 MiB
allocations per hop** for a one-second mel, now **~0.005 ms and no allocation**
(one dict lookup). The cost scales with clip length because the legacy payload
is `base64(JSON([...]))` — roughly 10–12 bytes of text per float. A five-minute
clip multiplies this by ~300. The research estimate (40–80 ms, 35–45 MB churn)
is the same order for short clips and larger for long ones; either way the
serialization is pure waste because both endpoints are in the same process.

Reading the counts:

- `decode_calls == 2` for two requests means **exactly one boundary decode per
  request**, no matter how many pipeline steps consume the audio. Before Phase 2
  the OpenVoice V2 clone path decoded the reference audio three times (Whisper,
  tone-converter encoder, and again for the tone converter's target check).
- `encode_calls == 0` confirms the engine core performs no wire encoding. Only
  the serving boundary (`wire.to_wire_audio`) encodes a final response; the
  benchmark calls the engine directly, and the determinism hashes are computed
  outside the counter window.
- Per-step times are dominated by model inference, not serialization:
  OpenVoice V2 = Whisper 0.38 s → TCE 0.014 s → MeloTTS 1.27 s → TC 0.70 s;
  HarmonySpeech = encoder 0.09 s → synthesizer 0.10 s → vocoder 0.06 s;
  VoiceFixer = restorer 0.48 s → vocoder 2.06 s.
- CPU wall time on this host varies 2–3× between runs (observed VoiceFixer full
  request 0.83 s cold / 2.5 s under load; MeloTTS 28 s on its first request,
  1.3 s warm). Treat absolute numbers as relative indicators; the preserved
  properties (single decode, zero internal encode, determinism) are stable.

## Determinism (post-Phase-2 repeatability)

| family | waveform bytes | duration delta | RMS delta | interpretation |
|---|---|---|---|---|
| voicefixer | identical (SHA-256 equal) | 0 % | 0 % | deterministic |
| harmonyspeech | identical (SHA-256 equal) | 0 % | 0 % | deterministic |
| openvoice_v2 | differs (SHA-256) | 1.46 % | 1.17 % | MeloTTS samples noise (`noise_scale > 0`); stochastic by design |

The comparison is post-Phase-2 versus post-Phase-2 (repeatability). The
**pre-Phase-2 fixture comparison** (same inputs/seeds against commit `06e08dd`)
was not run: it requires a second checkout/worktree and a separate environment
for the old code. The artifact bus only changes the in-process container, so
byte-identical outputs for the deterministic families and the sampling-only
spread for MeloTTS are the expected shape of that comparison; recording it
remains a manual follow-up.

## Not measured here

- GPU absolute latency (`torch.cuda.max_memory_allocated` reports `0.0 MiB`
  because these runs were CPU-only). `--device cuda` configs can be added to
  `_family_configs` when a GPU host is available.
- The final serving-layer encode (`wire.to_wire_audio`). The unit test
  `test_to_wire_audio_from_artifact_matches_legacy_payload` proves it is
  byte-identical to the legacy payload; its cost is one WAV encode, exactly what
  the executor used to do.
- Chatterbox families (weights not part of this benchmark config); their hops
  are covered by unit tests (`test_artifact_hops.py`, `test_prepare_artifacts.py`).
